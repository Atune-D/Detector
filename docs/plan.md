# 证词矛盾检测：判断与评分方案

**AI 整理事实 → 配对 → 检查相关条件 → 比较是否冲突 → 程序评分 → 展示原文。**

目标是把判断过程做得清楚、可测试、容易解释。沿用现有项目，按模块逐步修改，不整套重写。

---

## 1. AI 负责整理事实和提出候选，不负责打分

每条事实保留：

| 字段 | 说明 |
| --- | --- |
| 人物 | 这条事实说的是谁 |
| 动作或状态 | 归入受控词表，如 `location.home`、`sleep_onset`、`knows_of` |
| 对象、地点 | 实体及其粒度（仓库 / 那一带） |
| 事件时间 | 原始表达 + 解析后的范围（见 §3.2） |
| 极性 | 肯定、否定，或无法确定（如 "I don't think…"） |
| 否定形式 | 否定作用在什么上：整句否定（"整晚都不在家""从没去过"）、对"全部"的否定（"没有整晚在家""不是每次"）、对确定性的否定（"不确定是否在家"）。不能把后两种压缩成普通否定 |
| 状态来源 | 该状态是原文直接表达的，还是从某项活动推导出来的。推导出来的必须保留原始活动，不能改写成状态 |
| 不确定表达 | 标记词，以及它修饰的是动作、时间还是他人行为 |
| 来源 | 所属问答、原文引用、字符位置 |

规则：

* 一个回答可以拆成多条事实。
* 抽取时可以看同一份证词的上下文（日期、指代、后续更正），看不到另一份证词。
* 不合并含义不同的谓词，"没见过他"和"没听说过他"是两条。
* AI 可以建议哪些事实值得比较，建议只决定"比不比"，不产生任何结论。
* AI 不输出分数；程序也不读取 AI 给出的任何置信度。

**原文引用由程序定位校验。** 定位不到的引用，该候选标记为分析异常。

---

## 2. 配对时按事实内容，不要求两个问题相同

候选 = 两份证词各一条事实 + **一种比较类型**。配对条件：

| 比较类型 | 配对条件 |
| --- | --- |
| 否定 | 同一人物、同一谓词 |
| 时间 | 同一人物、同类事件 |
| 状态 | 同一人物、各描述一个状态 |
| 推理模板 | 同一人物，且符合某个已实现模板的形状 |

* 来源有两个：程序按上表配对，AI 提名。两者合并去重。
* 不靠措辞相同来配对，也不把不同日期、不同次事件强行合并。
* **每条候选只交给它那一种比较类型的比较器。** 其他比较器不参与，也不能影响结果。
* **没有具体冲突理由就不建候选。** 两条明显无关的事实（"订过披萨"和"认识 Tom"）不进入任何分区。只有已经提出了理由、但系统无法核验的候选才进待复核。

**直接比较还是推理模板**（项目约定的分类口径）：

分界看**状态是不是原文直接表达的**，不看句子里有没有活动：

| 原文 | 状态依据 | 路由 |
| --- | --- | --- |
| "当时不止我一个人" | 原文直接说了有人在场 | 状态比较 |
| "我在上海开车" | 地点"上海"由原文直接给出 | 状态比较 |
| "Tom 在同一房间和我面对面交谈" | "不是独处"要从活动推出 | 推理模板 |
| "我给 Tom 打了电话" | 推不出 Tom 与自己共同在场 | 不触发共同在场模板 |

* 状态比较只接受"状态来源 = 原文直接表达"的事实。来源是推导的事实只能进推理模板。
* 即使抽取器把"面对面交谈"写成了"有人在场"，只要状态来源标的是推导，仍走模板。
* 同一对事实的同一条推断路径只生成一条候选，不会同时出现 85 和 75。

**配对只产生候选。** 无论候选来自程序还是 AI 提名，比较器都要重新检查人物、谓词关系和当前规则需要的范围条件，不能因为被提名了就跳过。

## 3. 比较器

四个独立函数，接口相同：

```ts
interface CompareResult {
  result: "conflict" | "compatible" | "unknown";
  ruleId: string;
  evidenceRefs: EvidenceRef[];
  missingConditions: string[];   // result="unknown" 时列出缺什么
  assumptions: string[];         // 结论依赖的默认策略，如 "evening 范围取自词表"
}
```

**只有必要条件全部确定时，才能返回 `conflict` 或 `compatible`。** 其余一律 `unknown`。"没检测到冲突"不等于"确认兼容"。

条件的依据分两种：**证词明确支持**的，和**按词表或容差策略推定**的。结论只要用到后一种，就必须写进 `assumptions`，界面如实显示，不能写成"原文已确认"。

### 3.1 否定比较（`R_NEGATION`）

进入下表之前，比较器先自己确认三件事，任何一件不满足就返回 `unknown`：

* 两条事实是同一人物。
* 谓词相同，或两个谓词之间有登记过的关系规则。"没看见 Tom"和"跟 Tom 说过话"谓词不同且无关系规则，不能套用否定规则。
* 否定形式是**整句否定**。"没有整晚在家""不是每次""不一定""不确定是否"这些形式 V1 不解析，一律 `unknown`。

| 情况 | 结果 |
| --- | --- |
| 极性相反；对象相同；肯定一方的时间落在否定覆盖的时段内 | `conflict` |
| 极性相反；对象有包含关系，且该谓词登记了包含规则，按规则可推出冲突；时间条件同上 | `conflict` |
| 极性相反；对象有包含关系，且按该谓词的包含规则推不出冲突（否认去过仓库，承认经过那一带） | `compatible` |
| 极性相反，但时间明确在否定时段之外（去年不认识，今年认识） | `compatible` |
| 极性相同 | `compatible` |
| 对象有包含关系，但该谓词没有登记包含规则（没买过整栋楼，买过其中一套公寓） | `unknown` |
| 极性无法确定、对象关系无法解析、任一方时间未锚定 | `unknown` |

**包含规则和谓词关系规则**写在代码里，V1 只登记这两条：

* 进入类谓词（`been_to`、`entered`）的包含规则：进入内部空间意味着进入其所在的建筑或区域；反过来，到过更大的区域不意味着进入其中某个具体地点。
* `passed_through`（经过）与 `been_to`（去过）的关系：经过一片区域不意味着去过其中的某个具体地点。样本里"没去过仓库"和"开车经过那一带"靠这一条判兼容，而不是把两个谓词当成同一个。

没有登记的谓词组合返回 `unknown`。

### 3.2 时间比较（`R_EVENT_TIME`）

先确认是同一次事件。只有两种依据：

* 证词明确指向同一次（"那次到达""第一次睡着"）。
* 两条回答针对的是同一个问题，且指向同一个日期或时段（两次都被问 "What time did you go to sleep?"，都指 11 月 3 日当晚）。这是推定，写进 `assumptions`。

同一天、同一晚可能发生多次的动作（到达、外出、睡着）不能仅凭类型和日期相同就视为同一次。

| 情况 | 结果 |
| --- | --- |
| 同一次事件，两个可能范围不相交 | `conflict` |
| 同一次事件，两个可能范围相交 | `compatible` |
| 明确不是同一次事件 | `compatible` |
| 无法确定是否同一次，或时间无法解析 | `unknown` |

**精度策略**（版本化配置，初始值未经数据校准）：

| 表达 | 可能范围 |
| --- | --- |
| 带精确标记（exactly / sharp） | 不放宽 |
| 无标记的时刻 | ±5 分钟 |
| around / about / roughly | ±20 分钟 |
| maybe / I think / probably | ±30 分钟 |

同一表达上有多个标记时取最宽的一个，不叠加。"10, maybe 10:30" 先解析为 22:00–22:30 再放宽。

### 3.3 状态比较（`R_STATE`）

持续状态有两个范围：**确定范围**和**可能范围**。

* 用明确钟点给出的边界：两者相同，属于证词明确支持。
* 边界带模糊词：确定范围向内收、可能范围向外放，幅度同 §3.2，属于策略推定。
* "evening" 这类词查表（初始值：确定 18:00–21:00，可能 17:00–24:00），属于策略推定。这是产品假设，不是原文保证。

"时间确认重叠" = 两个确定范围相交，或一方的可能范围完全落在另一方的确定范围内。

边界约定：

* 持续区间一律是半开区间 `[start, end)`。"20:00–21:00 在家"和"21:00–22:00 在外"只在端点相接，不算重叠。
* 精确时刻的事件按一个点处理，落在 `[start, end)` 内才算在区间里。
* 确定范围向内收之后可以为空（"大约 8:00 到大约 8:20"两端各收 20 分钟）。空范围表示没有能保证覆盖的时段，**不能参与"确认重叠"**；不得交换起止点把它修成有效区间。

| 情况 | 结果 |
| --- | --- |
| 时间确认重叠，且两个状态在互斥表中互斥 | `conflict` |
| 关系表明确登记两个状态可以并存 | `compatible` |
| 两个可能范围不相交 | `compatible` |
| 只是可能重叠，或关系表里没有这个组合 | `unknown` |

**状态关系表写在代码里，不由 AI 判断。** 只登记具体、有限的条目，不按整个维度放行：

| 组合 | 处理 |
| --- | --- |
| 在家 vs 外出（`location` 同维不同值） | 互斥 |
| 睡眠中 vs 清醒（`sleep_state`） | 互斥 |
| 独处 vs 有人在场（`company`，两边都是显式状态描述） | 互斥 |
| 在家 + 看电视 | 可并存 |
| 订披萨 + 买菜 | 可并存（两件事本身不互斥） |
| 在家 + 在别处进行的活动 | 不登记；先把活动的地点抽成一条 `location` 事实，再按"在家 vs 外出"比 |
| 地点之间关系未知（"停车场"是否在住处范围内） | `unknown` |
| 没有登记的组合 | `unknown` |

`sleep_state` 的取值是"睡眠中"，不是"入睡"。入睡是事件，归时间比较；睡眠中才是持续状态。

### 3.4 固定推理模板（`R_TEMPLATE_*`）

模板的全部槽位都确定成立才返回 `conflict`；否则返回 `unknown`。模板不返回 `compatible`。

**`R_TEMPLATE_ALONE_VS_COPRESENT`**

1. 两条事实是同一人物。
2. A 明确表示在某一时段、某一空间范围内始终独处。
3. B 描述了一项活动，该活动意味着另一人**实际**与其共同在场（面对面交谈满足；"可能被看见"不满足）。
4. B 的共同在场确认发生在 A 的时段内（标准同 §3.3）。
5. B 的共同在场发生在 A 所说的空间范围内。范围对不上或无法确定时不成立。

V1 只交付这一个模板。

**暂不实现：睡眠后仍在活动。** "10 点睡着"和"11 点接了电话"不矛盾，因为没提到醒来不等于没醒来。将来要做，条件必须是：A 明确声称在某个时段内持续睡眠、未醒来，且 B 的清醒活动确认发生在该时段内。在此之前，这类候选一律待复核。

已提出推理理由但没有对应模板的候选，直接待复核。

## 4. 评分

一个纯函数，只读取比较结果和不确定表达：

| 比较结果 | 类别 | 分数 |
| --- | --- | --- |
| `conflict`，来自否定 / 时间 / 状态比较 | 直接矛盾 | 85 |
| `conflict`，来自推理模板 | 推理矛盾 | 75 |
| `compatible` | 误报 | 不评分 |
| `unknown` | 待复核 | 不评分 |
| 原文引用无效 | 分析异常 | 不评分 |

**不确定性扣分**：冲突所依据的动作或状态上有不确定表达（"I think I went out"）时扣 10，每条候选至多一次。以下两种不再扣：

* 时间上的模糊词，已经用于放宽时间范围。
* 已经导致某个条件为 `unknown` 的模糊词。

全部可达分值：85、75、65。数字是版本化的初始参数，不是概率，界面不加 `%`。不评分时显示状态标签，不显示 0。

每次评分记录：规则版本、`ruleId`、基础分、最终分、缺失条件、`assumptions`。有扣分时，记录扣的是哪条事实里的哪个标记词及其原文位置。相同输入必须得到相同输出。

## 5. 界面

每条结果显示：

* 类别，以及分数或"待复核"。
* 两边的原文，点击可定位高亮。
* 触发了哪条规则。
* 不确定因素，或缺失的条件。
* `assumptions` 非空时，**卡片上直接显示"依赖默认策略"标签**，不藏在展开详情里；详情里列出具体是哪条策略。这类卡片的分数表示"在当前策略下满足冲突规则"，不表示原文已明确确认。

评分明细由 §4 的评分记录直接渲染，不由 AI 生成文字。

三个分区：矛盾（直接 / 推理）、待复核、已排除（误报，默认折叠）。分析异常单独列出。

运行状态：

| 情况 | 显示 |
| --- | --- |
| 正常完成，有候选 | 结果列表 |
| 正常完成，候选为空 | "本次分析未发现候选"（不保证没有遗漏） |
| 部分候选分析异常 | 结果列表 + 异常项，注明部分失败 |
| 上游超时、返回缺失、结构错误或截断 | 分析失败 |

## 6. 验收案例

### 6.1 行为案例

| 输入 | 比较器 | 预期 |
| --- | --- | --- |
| 同一晚"一直在家" vs "出去买菜" | 状态 | 直接矛盾，85 |
| 同上，但后者是 "I think I went out" | 状态 | 直接矛盾，75 |
| "订披萨" vs "买菜" | 状态 | 误报 |
| 昨天在家 vs 今天在商场 | 状态 | 误报（时间不相交） |
| "20:00–21:00 在家" vs "21:05–21:15 在超市" | 状态 | 误报 |
| 在家 vs 在停车场挥手，停车场位置不明 | 状态 | 待复核 |
| 同一时段"始终在家" vs "在外地开车" | 状态 | 直接矛盾，85（开车地点抽成 `location` 后与在家互斥）；不得凭跨维度直接判误报 |
| "只有我一个人" vs "当时不止我一个人" | 状态 | 直接矛盾，85 |
| 同一次到达"大约 8 点" vs "8:05" | 时间 | 误报 |
| 同一次到达"准确 8:00" vs "准确 8:05" | 时间 | 直接矛盾，85 |
| 证词明确说明是两次不同的外出，时间不同 | 时间 | 误报 |
| 两个外出时间不同，无法确定是不是同一次 | 时间 | 待复核（是否同一次事件） |
| 没去过仓库 vs 开车经过附近 | 否定 | 误报 |
| 没进过仓库 vs 去过仓库里的办公室 | 否定 | 直接矛盾，85 |
| 没买过整栋楼 vs 买过其中一套公寓 | 否定 | 待复核（该谓词没有包含规则） |
| 去年不认识 vs 今年认识 | 否定 | 误报 |
| 办公室始终只有自己 vs 同一时段与 Tom 在该办公室面对面交谈 | 模板 | 推理矛盾，75；只出这一条，不同时出 85 |
| 办公室始终只有自己 vs 同一时段与 Tom 在楼下大厅交谈 | 模板 | 待复核（空间范围对不上） |
| 10 点睡着 vs 11 点有活动，没说是否醒过 | 无模板 | 待复核 |
| "订过披萨"和"认识 Tom"，没有人提出冲突理由 | - | 不建候选 |
| "没有整晚在家" vs "8 点在家" | 否定 | 待复核（否定形式不支持）；不得判冲突 |
| "整晚都不在家" vs "当晚 8 点在家" | 否定 | 直接矛盾，85 |
| "没看见 Tom" vs "和 Tom 说过话" | 否定 | 待复核（谓词不同且无关系规则） |
| "面对面交谈"被抽取器写成"有人在场"，状态来源标为推导 | 模板 | 仍走模板，不进状态比较 |
| "给 Tom 打了电话" vs "始终只有自己" | 模板 | 待复核（推不出共同在场） |
| 持续状态收缩后确定范围为空 | 状态 | 待复核；不得确认重叠 |
| "20:00–21:00 在家" vs "21:00–22:00 在外" | 状态 | 误报（只在端点相接） |
| 原文引用不存在 | - | 分析异常 |
| 正常分析没有候选 | - | 成功完成，结果为空 |

### 6.2 样本证词（Marcus Webb，3 月 vs 9 月）

| 3 月 | 9 月 | 预期 |
| --- | --- | --- |
| "at home all evening" | "I think I went out briefly… maybe around 7:30" | 直接矛盾，75 |
| "ordered pizza around 7pm" | "get some groceries" | 误报 |
| "Around 10, maybe 10:30" | "Midnight maybe" | 直接矛盾，85 |
| "No, I was alone" | "Tom might have seen me. We waved or something" | 待复核（Tom 是否实际在场） |
| 没去过 Hargrove Street warehouse | 开车经过那个 area | 误报 |
| "I'd never heard of him before this whole thing started" | "I knew of him" | 待复核（"knew of him" 的时间未锚定） |
| "Had you met…? No." | "I don't think I'd met him face to face" | 待复核（极性无法确定） |

有两条结论依赖默认策略，结果里必须带 `assumptions`，且只作回归测试用，不能反过来证明策略合理：

* **在家 vs 出门**：依赖 "evening" 的确定范围覆盖 19:00–20:00。测试输入要包含对应的问题、"11 月 3 日当晚"的时间指向和所用策略版本，不能只给两句引文。
* **入睡时间**：依赖两点。一是放宽幅度（放宽后 21:30–23:00 与 23:30–24:30 不相交）；二是"同一个问题 + 同一晚"被推定为同一次入睡。如果不接受第二点，这条应改为待复核。

### 6.3 测试分层

* **比较器单元测试**：直接构造两条事实，断言 `result` 和 `missingConditions`。
* **评分单元测试**：构造比较结果，断言精确分数。
* **端到端测试**：从原文到界面，用 §6.2 的样本，分两种运行方式。
  * **回放**：使用保存下来的抽取结果，精确断言比较结果、分数和界面。
  * **真实调用 LLM**：检查抽取错误、漏检和结果波动，不断言精确分数。

  两种分开跑，模型偶尔抽错时能看出问题在抽取阶段，而不是评分代码不确定。

## 7. 实施顺序

1. 打通"一直在家 vs 出门"一条端到端流程：抽取、原文定位、状态比较器、评分、展示。
2. 时间比较器和精度策略。
3. 否定比较器。
4. 独处模板。
5. 待复核和已排除分区、空结果和失败状态。

每完成一个比较器，先把 §6.1 里对应的反例全部跑通，再做下一个。
